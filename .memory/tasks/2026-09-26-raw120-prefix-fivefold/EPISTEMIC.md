# Current model

## Target and mechanism
The deliverable is accepted physical prefix + policy manipulation + offline retreat rows, five per raw source. Five retries cannot satisfy that contract; slot identity must be separate from attempt identity and durable acceptance must drive completion.
Prefix variation primarily changes approach motion. Once it reaches the same pre80 reference, repeatedly changing seeds may not repair a policy that systematically fails manipulation. A persistent queue must preserve these deficits and surface them for diagnosis rather than burn both GPUs on the same source or count replacements from easier sources.

## Supported facts
Completed inventory and task scope are recorded in OPS.md (baseline entry). Historical runner uses homogeneous-object GPU waves and solved contacts, but creates runtime per wave. Historical prefix samples Far/Near position and copies source hand orientation/fingers; it does not yet implement the requested source-relative 5–50 cm plus posture distribution. Base pre-padding is a configurable parameter, not necessarily a new decoder requirement.

## Live uncertainties
- Can the existing runtime replace references/reset without recompiling while retaining correct checkpoint semantics and pre80 policy timing?
- Which throughput limit dominates at useful batch sizes: GPU physics, host state/contact materialization, or repeated compilation/export?
- Do CCD16 and contact/constraint buffers truncate contacts in this inference workload? Live CCD counter can be unavailable.
- What fraction of individual sources passes manipulation and has a sufficiently long contact-free tail for offline retreat?

## Commitments
Preserve trained control/asset/time contracts. Implement the smallest reusable extension, use real acceptance gates, and benchmark complete saved-row throughput. No guarantee of zero overflow or universal synthesis success follows from configured capacity or completed PPO updates.
