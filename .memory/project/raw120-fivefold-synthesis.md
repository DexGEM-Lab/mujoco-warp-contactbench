# Raw120 fivefold synthesis

Canonical guide: `docs/manorl_raw120_fivefold_synthesis.md`.

Each retained raw source owns five accepted saved slots, independent of retry count.
The current opt-in policy skips incomplete sources below25% durable rows per
settled generation attempt, after at least20 settlements. Existing data and
in-flight claims are preserved; skipped slots are never counted as successes.
Original inventory and retained/effective targets are separate status fields.
Historical pre60 Far/Near remains separate. New prefixes preserve the trained
early80 AFTER augmentation and join native-servo-clipped finger targets; raw
MANO PIPs can violate physical limits without invalidating the training reference.
Do not rewrite the original manipulation reference to make prefix checks pass.

Compact rows retain actual Warp solved contacts. Offline retreat changes wrist
XYZ and dependent keypoint/kinematic target translations, and rejects added
geometry penetration versus the original solved baseline. Existing compliant
floor overlap is not automatically a new retreat collision.

A local SQLite ledger claims source/slot pairs. Only checksum/readback-verified
NAS publication counts as acceptance; recovery reconciles promoted shards before
releasing dead-owner claims. Owner locks survive in CPU publishers. A server
watch process, not an indefinitely waiting LLM, owns process continuity. Initial
filter activation on a large ledger requires a writer drain for index creation.
Do not declare campaign completion while publication blockers/workers remain.
If remaining group slots cannot hold two full batches, pending publication can
make the next claim short. Settle it before padding that short claim, then reclaim
only failed slots; full claims retain overlap. This fills the initial batch, not
mid-rollout finished envs. Compare actual candidates with fixed world count.

Benchmark accepted published rows/GPU-hour using fixed candidates and separate
outputs. Contact/constraint capacity and CCD warning visibility are explicit;
no configured capacity alone certifies zero truncation.
